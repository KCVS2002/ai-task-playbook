# 과제 유형별 검증

현재 과제에 해당하는 부분만 읽습니다. 여기의 예시는 실제 과제의 요구사항을 대체하지 않습니다.

## 데이터 분석·집계

- 한 행이 나타내는 대상, ID, 단위, 기간을 먼저 확인합니다.
- 누락·중복·이상값 처리 기준을 업무 조건과 연결합니다.
- 전체 비율은 올바른 분모와 가중치를 확인합니다. 그룹 비율의 단순 평균과 구분합니다.
- 조인 후 행 수와 키 유일성을 확인해 중복 집계를 발견합니다.
- 원본을 보존하고 제외된 행과 사유를 구분합니다.
- 작은 표본은 직접 계산한 기대값과 대조합니다.
- 근거 없는 인과관계나 데이터가 뒷받침하지 않는 결론을 쓰지 않습니다.

## 예측·분류

- 입력, 예측 대상, 실제 사용 시점, 평가 지표를 정의합니다.
- 평가 시점에 알 수 없는 정보가 입력에 들어가는지 확인합니다.
- 시간·Lot·장비·사용자처럼 데이터가 묶이는 구조를 고려해 분할합니다.
- 간단한 기준 모델이나 규칙과 비교합니다.
- 전체 평균만으로 중요한 실패 구간을 가리지 않습니다.
- 실제 측정한 성능과 계획만 세운 검증을 구분합니다.
- 모델 학습이 과제에 필요하지 않으면 임의로 추가하지 않습니다.

## 웹·API

- 먼저 최소 흐름을 실행하고 기존 서버 설정을 유지합니다.
- 제공 미리보기에 필요한 호스트·실제 포트·경로를 확인합니다.
- 핵심 정상 경로와 빈 입력·잘못된 입력·서버 오류 등 중요한 실패 경로를 확인합니다.
- 화면만 바뀌고 실제 처리가 되지 않는 임시 기능을 완성으로 보고하지 않습니다.
- 사용자가 제공 Browser에서 직접 조작합니다. 금지된 자동 조작 도구를 연결하지 않습니다.
- 재시작 후에도 문서의 실행 방법으로 동작하는지 확인합니다.
- 인증·권한이 요구되지 않으면 불필요하게 추가하지 않습니다.

## 문서·보고서·표

- 독자, 목적, 필수 구성, 파일 형식을 확인합니다.
- 수치와 결론의 원본 근거를 추적할 수 있게 합니다.
- 표·본문의 값, 단위, 합계가 일치하는지 확인합니다.
- 생성한 파일이 열리는지, 중요한 표·그림·문장이 잘리지 않는지 확인합니다.
- 사실·해석·권고·미확인 사항을 구분합니다.
- 실제로 생성하지 않은 파일을 완료 목록에 넣지 않습니다.

## 업무 자동화·연동

- 입력, 처리, 출력, 사람이 승인할 결정을 구분합니다.
- 읽기 전용 요구를 쓰기 작업으로 임의 확대하지 않습니다.
- 실제 연동과 샘플·모의 처리를 구분합니다.
- 중복 입력이나 재실행이 어떤 영향을 주는지 확인합니다.
- 외부 전송·계정 접근이 허용되지 않으면 로컬 처리 대안을 검토합니다.
- 과제 목표에 필요한 범위만 구현합니다.

## 자기 설명 점검: AI 사용이 허용된 작업 단계에서

- 어떤 문제를 어떤 범위로 해결했는가?
- 입력부터 결과까지 어떻게 처리되는가?
- 중요한 선택을 왜 했는가?
- 무엇을 실제 실행·검증했는가?
- 어떤 실패 조건과 한계가 남아 있는가?

AI 사용이 금지된 후속 단계에서는 AI 요청이나 자동 답변 지원을 중단합니다.
